## Contre-audit du test de redirection

Le premier échec n'est plus une hypothèse. Un listener `127.0.0.1` ouvert pour vérification a reçu une connexion. Le socket pair, lu dans `/proc/net/tcp`, appartient à `/usr/local/bin/xai-grok-preview-proxy`, processus distinct de la suite. Il se connecte aux ports loopback nouvellement liés et n'envoie pas la requête HTTP du moteur. L'ancienne assertion (`accept()` doit lever `SocketTimeoutException`) échoue dès qu'il se connecte, même si OkHttp ne suit pas la redirection.

Le moteur n'est pas modifié. Le test lit le client statique réel `LoopbackTransport.HTTP` et vérifie `followRedirects == false`, `followSslRedirects == false` et `retryOnConnectionFailure == false`. Il ne répond 302 qu'à une ligne `GET /challenge?client_nonce=`. Il échoue seulement si le listener appât reçoit une ligne contenant `/stolen`. Une poignée étrangère sans cette requête est ignorée.

Dix exécutions isolées de `redirectDoesNotReachAnotherLoopbackEndpoint` ont réussi. La suite complète a ensuite été relancée : **357 suites, 1722 tests, 0 échec, 0 erreur, 0 ignoré**. Le XML de `SentinelAiLocalHttpTest` porte l'horodatage `2026-11-25T16:39:52Z`. Le test est déterministe sur cet hôte. Il ne démontre pas que l'application ouvre la base V25 du S24+ ni qu'elle y retrouve 29 décisions.

Le classement des 245 avertissements est dans `LINT-CLASSIFICATION-20261125.md`. Aucun contrôle n'a été désactivé.

## Toujours hors qualification

- Préflight Termux et suite sur le S24+ : non faits.
- Instrumentation ARM64 : non faite. Cet hôte n'a ni image système Android ni `/dev/kvm`. Le profil commercial ne produit qu'`arm64-v8a`. `V25RoomIdentityUpgradeInstrumentationTest` efface uniquement la base synthétique de son contexte d'instrumentation ; il n'a pas été exécuté, et il ne doit pas l'être contre la base du téléphone.
- Sonde `OPEN_READONLY` : un échec de lecture (WAL / `-shm`) refuse l'ouverture au lieu de détruire. Ce faux négatif n'est pas démontré sur la base réelle, et il n'est pas « réparé » par une ouverture en écriture.
- `prune(500)` peut encore retirer des décisions au-delà de 500 lors d'un nouvel enregistrement.
- La clé privée du certificat debug installé sur le S24+ n'est pas dans le dépôt. Un APK signé autrement ne peut pas mettre à jour V25 sans désinstallation. Aucun `versionCode` supérieur à 25 n'est préparé.
