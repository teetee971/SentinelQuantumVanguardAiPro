## Statuts sans ambiguïté

- **Implémenté** : logique/parcours présents dans les sources citées ; cela ne signifie pas testé sur appareil.
- **Bloqué** : prérequis réellement manquant ou sonde en erreur (PTT ready503, permissions/SIM/backend selon runtime).
- **Non développé / non pris en charge** : modèle riche de contacts Sentinel indépendant et transformation audio native d’appel SIM absents du produit courant.
- **Simulé** : aucune simulation de données d’utilisateur ou de disponibilité ajoutée dans cette PR. Les doubles Redis des tests backend sont des fixtures de test explicites, pas un serveur de production ; la salle PTT de démonstration n’est pas une preuve de service public.
- **Conformité D.1 non validée** : références reçues, mais aucune capture réelle du candidat acceptée ; les tests unitaires ne prouvent pas la fidélité graphique.

Les tests de rendu/navigation existants couvrent une partie des états sans permission. Les scénarios en appel, SMS réels, contacts enrichis et périphériques connectés nécessitent un appareil et des données de test autorisées. L’écran SecurityLabPro a sa couverture dédiée mais n’est pas ajouté artificiellement à la liste historique des captures NavGraph sans exécution.
