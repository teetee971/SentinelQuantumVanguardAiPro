4.2 Contrôle d'isolation

Le scanner canonique excluait explicitement des workflows contenant des motifs
interdits à des fins de détection. Le contrôle Git indépendant ne les excluait
pas tous et produisait donc un faux positif. Les exclusions ont été alignées
sans retirer de règle de détection sur le code applicatif.

Résultat : npm run test:isolation passe ; contrôle de pinning des Actions passe.

4.3 Build Android

Cause observée : le workflow de build debug échouait durant la configuration
Gradle car les secrets de signature release étaient obligatoires, même pour
assembleDebug.

Correction :
- la configuration de signature release n'est créée que si les quatre variables
  de signature sont présentes ;
- toute tâche contenant « release » reste bloquée si elles sont absentes ;
- les builds debug peuvent donc rester non signés sans secret ;
- versions Gradle/AGP/Kotlin alignées dans les fichiers Gradle.

État : la validation de configuration locale reste bloquée par l'impossibilité
de résoudre le plugin Android depuis le dépôt Google dans cet environnement.
Le mode fail-closed des releases a été conservé.

mais GitHub le refuse car CodeQL Default Setup est simultanément activé dans les
paramètres du dépôt.

Message GitHub observé :
"CodeQL analyses from advanced configurations cannot be processed when the
default setup is enabled."

Action requise :
Settings -> Code security -> Code scanning -> CodeQL analysis ->
désactiver Default setup.

Le workflow .github/workflows/codeql-analysis.yml doit être conservé. Le
désactiver pour obtenir un statut vert supprimerait l'analyse avancée et ne
constituerait pas une correction acceptable.
